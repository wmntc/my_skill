# 推断指南与成品规范

本文件是 AI 的工作手册。教师**不填任何表**，以下所有内容都由 AI 从材料中推断得出。

## 一、通读材料：到哪里找信息

按优先级在材料中挖掘事实（这些都是**不需要问教师**的）：

| 信息线索 | 常见藏身处 |
|---|---|
| 教师姓名 | 文件名、文件夹名、文档正文署名、文档作者属性、对话记录中的称呼、文中"我"的身份描述 |
| 案例主题 | 材料标题、文件名、课件首页、开头的需求描述 |
| AI 工具 | 文中提到的产品名、截图中的应用界面、提示词里的工具调用 |
| 实施过程 | 课件目录、教案步骤、对话记录里"第1步/第2步"、操作截图序列 |
| 成效数据 | 表格文件、文中"从…降到…""提升了…"、成绩单/统计图 |
| 时间地点班级 | 文件属性创建时间、文中"本学期""七年级""东校区" |
| 荣誉佐证 | 文件名含"获奖/公开课/发表"、荣誉证书图片、获奖文件 |
| 学生声音 | 作文、感言截图、心得记录、访谈文字稿 |

- **图片必读**：教师会用图片承载大量信息。读图判断它在讲什么，并把文件名作为线索。
- **docx 重点看三处**：正文段落、表格、页眉页脚/批注——教师常把关键信息塞在表格里。
- 教师若只交了一段口述/聊天记录，就以这段记录为主要素材推断，其余字段能从记录里推出多少算多少。

## 二、元信息卡 14 字段：如何推断

以下字段**全部由 AI 推断**，括号内是推断线索。只有「负责人姓名」在找不到时才可能需要问。

| # | 字段（固定名） | 推断方法（括号内为线索） |
|---|---|---|
| 1 | 案例编号 | 一律留空，备注"汇编时由学校统一编号" |
| 2 | 案例名称 | 从材料主题提炼，≤20字，能看懂做了什么（如材料讲 AI 诊断分层教学→"AI学情诊断助力分层教学"） |
| 3 | 副标题/金句 | AI 拟一句 ≤22字、有传播力的点睛话，概括价值或反差 |
| 4 | 分类 | 从材料性质归入五选一：课堂教学/教师发展/学校管理/学生素养/家校协同（材料讲老师怎么用工具提效→教师发展；讲课堂怎么用→课堂教学；以此类推） |
| 5 | 学科/领域 | 从材料提取学科（讲数学=数学；讲跨学科=跨学科；讲行政=行政管理） |
| 6 | 适用学段 | 从材料提取（七年级/初中全学段/全学段） |
| 7 | 核心AI工具 | 从材料中提到的工具名汇总（产品名、截图界面、提示词）；无则"未提及" |
| 8 | 负责人 | 从材料找真实姓名+职务；**完全找不到才澄清**；仍无则写"教师未提供" |
| 9 | 团队成员 | 从材料提取；无则写"无" |
| 10 | 实施时间 | 从材料提取（文件时间、"本学期"、文中起止月份）；无则写"未提供" |
| 11 | 涉及校区/班级 | 从材料提取；无则写"未涉及" |
| 12 | 一句话简介 | AI 基于全部材料概括，≤40字 |
| 13 | 关键词 | AI 提炼 3~5个，顿号分隔 |
| 14 | 成果级别 | 从材料判断（校内做法=校内试点；已推广/获奖发表则相应上调）；无依据写"校内试点" |

## 三、正文七栏目：从散材料组织成文

AI 把分散在多份材料里的信息，按下面七栏重组为连贯段落。每栏要求与来源提示：

| 栏目 | 内容要求 | 从材料哪里取 |
|---|---|---|
| 一、背景与问题 | 具体痛点，非空话（150~300字） | 教师口述的开头、需求描述、问题陈述 |
| 二、解决方案与实施过程 | 分步骤叙述，能看懂"怎么做"（400~800字） | 课件/教案步骤、对话记录中的实施过程、截图序列 |
| 三、AI工具与技术要点 | 各工具分工、选择理由、代表性提示词、数据安全（200~400字） | 提示词原文、工具界面截图、工具说明 |
| 四、成效与数据 | 具体数字+对比口径，或明确"暂无数据"（150~300字） | 表格、成绩/统计图、文中数字；数字务必辨明真假（见下） |
| 五、师生声音 | 引语有署名或匿名标注 | 教师/学生感言原文、访谈、作文 |
| 六、可推广性与建议 | 复用条件或一条建议（150~300字） | 教师总结、注意事项、推广设想 |
| 七、荣誉与佐证 | 有则注明时间级别，无则"无" | 获奖/证书/公开课文件 |

**成文纪律**：
- 可做：理顺语序、分段、合并重复表述、把口语转成书面语、统一格式。
- 不可做：添加材料中不存在的具体事实、编造数字或引语署名。材料没写的，宁可写"无/未提供"，也不虚构。

## 四、必须澄清项判定（只问这些）

**判定标准**：材料里完全没有 + 猜错会造成实质后果（署名错误、数据造假、隐私风险）。三者缺一不问。

只有以下三类值得问教师：

1. **教师真实姓名**——材料里完全找不到、成品又必须署真名时。给出材料中出现过的可能人名作为选项。
2. **成效数据真假**——材料里出现具体数字（尤其带百分比、天数、次数）时，必须确认是真实统计还是示例/待测数据。给选项："真实统计/示例数字/暂无数据"。
3. **学生隐私授权**——材料含学生正脸照片或可识别个人信息时，确认是否可用于公开印刷。给选项："可用/需替换为背影/从成品移除"。

**提问方式**：所有必须澄清项**合并成一次 AskUserQuestion（最多4 题）**，每题给出候选选项让教师点选。轮次上限 2 轮。教师说"你定就行"就直接采纳 AI 推断值。

## 五、教师确认摘要格式（出成品前给教师看）

在生成成品文件**之前**，先向教师呈现以下摘要并请其确认/修改：

```
我已通读 N 份材料，整理出这个案例（请过目，有不对的地方告诉我）：

· 案例名称：XXX
· 所属分类：XXX
· 一句话简介：XXX
· 核心 AI 工具：XXX
· 七栏目要点：
  1 背景与问题：……
  2 实施过程：……
  ……
· 涉及的老师/班级/时间：……

还需你确认（点选即可）：
[AskUserQuestion 列出第四节的必须澄清项]

确认后我就生成成品文件夹。
```

教师确认或回复"可以/你定"后，再进入成品生成。

## 六、成品格式规范

### 目录结构
```
成品-<负责人姓名或简称>-<案例短名>/
├── 案例定稿.md
├── 案例定稿.docx
├── 附件/
├── 附件清单.md
└── 材料溯源与待确认.md
```
- 文件夹名禁用空格与 `#&` 等符号。

### 案例定稿.md
- 结构：填写人信息 + 「第一部分：元信息卡」+ 「第二部分：正文七栏目」。
- 元信息卡用固定字段名的 YAML 式代码块（字段名不可改，供管理端批量解析），`案例编号` 留空并备注"汇编时由学校统一编号"。

元信息卡字段顺序（固定）：
```
案例编号 / 案例名称 / 副标题/金句 / 分类 / 学科/领域 / 适用学段 /
核心AI工具 / 负责人 / 团队成员 / 实施时间 / 涉及校区/班级 /
一句话简介 / 关键词 / 成果级别
```

### 附件重命名
成品 `附件/` 内统一 `p<栏目号1~7>-<用途短词>.<原扩展名>`，如 `p2-课堂讨论.jpg`。重命名只发生在成品 `附件/` 内，待整理目录原始文件保持原样。

### 附件清单.md
AI 自动生成的表格：文件名 / 类型 / 对应栏目 / 图注说明 / 来源。与 `附件/` 内实际文件一致。

### 材料溯源与待确认.md（不可省略）
分三部分：
1. **关键结论溯源表**：成品中每个关键结论 → 依据哪份材料（如"收集周期 15天→3天 ← 来源：台账.xlsx"）。
2. **AI 推断项标注**：哪些内容是 AI 推断的（而非材料明写），标⚠️ 提示教师复核。
3. **待确认项**：教师尚未确认、或确实无材料支撑的项。

### 生成 docx
用隔离环境 python-docx 执行 `scripts/make_case_docx.py <成品目录>`，由 `案例定稿.md` 渲染出 `案例定稿.docx`。

## 七、补交与更新

教师补交材料放入成品文件夹（或待整理目录）后再次触发本技能，**只重做受影响文件**，其余保持不变。
