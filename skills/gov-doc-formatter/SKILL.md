# 公文格式排版（gov-doc-formatter）

把普通文本转成符合 GB/T 9704-2012 版式规范的 .docx 公文。
核心脚本 `scripts/render_gongwen.py`：JSON 描述 → 标准公文 docx（字体自动嵌入）。

## 工作流程

### 第 1 步：获取内容并判定版式要素

从用户提供的文本/文档中提取：标题、主送机关、正文、附件、署名、成文日期等。

**必须先行判定的版头要素**（用户未明确时，先自行判断再向用户澄清，确认后才产出）：

| 要素 | 判断依据 |
|------|----------|
| 份号 | 一般公文不标；涉密公文必标（6 位数字） |
| 密级和保密期限 | 只有涉密公文标注，如「秘密★10年」 |
| 紧急程度 | 仅当用户说明时限要求（特急/加急） |
| 发文机关标志（红头） | 正式发文有；内部材料一般无 |
| 发文字号 | 正式发文有；格式「机关代字〔年份〕序号」 |
| 签发人 | 仅上行文（请示、报告）必标 |
| 印章 | 有印章图片则压署名排版；无则留空 |

澄清话术要点：一次列全，逐项让用户确认「需要 / 不需要 / 用什么内容」，不要反复追问。

### 第 2 步：构造 spec.json

字段说明见 `references/spec_schema.md`。要点：

- `body` 数组元素类型：`p` 普通段、`h1`~`h4` 层级标题（字体字号自动匹配国标）、`quote` 引文、`table` 表格、`blank` 空行
- 标题超过一行时脚本自动按词意断行并排成上长下短的梯形
- 发文字号、成文日期由脚本自动做合规校验（六角括号、不编虚位、标题不加句号等）

### 第 3 步：生成与校验

```bash
# 合规自检（不生成文件）
python scripts/render_gongwen.py spec.json --check

# 生成（自动嵌入字体，约 8MB）
python scripts/render_gongwen.py spec.json -o 输出.docx
```

- Python 用托管运行时：`C:\Users\Admin\.workbuddy\binaries\python\envs\default\Scripts\python.exe`（需 python-docx，已在环境中）
- 校验失败时把问题逐条报给用户，修正 spec 后重跑；确需忽略用 `--force`
- 字体嵌入失败（assets/fonts 缺失）会自动降级为本机字体，需提醒用户

### 第 4 步：交付前人工核验

用 Word/WPS 打开检查（或导出 PDF 检查）：

1. 红头单行居中、距版心上边缘 35mm
2. 红色分隔线与版心同宽
3. 首页有正文内容；版记在最后一页底部
4. 单页码居右、双页码居左
5. 印章压住署名与日期（如有）

## 版式常量（已内建于脚本）

A4；页边距上 37 下 35 左 28 右 26mm；版心 22 行 × 28 字。
标题二号方正小标宋；一级黑体、二级楷体加粗、三级仿宋加粗、四级仿宋（均三号）；正文三号仿宋_GB2312；页码四号半角宋体。红色取 C00000。

## 字体嵌入说明

`assets/fonts/` 内是三套字体的 GB2312 子集（各约 2~3MB）。生成 docx 时以
odttf 形式嵌入（fontKey 混淆 + fontTable 声明），Word 打开即用，无需本机安装。
嵌入使文件增大约 8MB，属正常现象；用 `--no-embed` 可关闭。

## 常见问题

- **红头折行**：脚本已按版心宽度自动缩小字号；若仍折行，检查 org_mark 是否过长
- **每行字数不对**：勿改动 `setup_section` 中的 docGrid 参数（charSpace 单位是 1/4096 磅）
- **WPS 兼容**：字体嵌入在 WPS 中同样生效；若个别版本不认，改为安装字体后 `--no-embed`
