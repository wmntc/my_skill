# 多模型教学设计生成

根据用户提供的课题标题，先用两轮澄清问题确认关键信息并选定教学设计模型，再按所选模型（单一模型或不超过两个模型的组合）撰写完整教学设计，最终一次性交付**三份文件**：A4 排版的静态网页教案（HTML）、可直接送打印机的 A4 PDF，以及便于传阅与再加工的 Markdown 文档。

## 交付形态（重要）

本技能交付的是 **HTML 静态网页教案**，不是 Word 文档。每次交付**三份文件**：

| 文件 | 生成脚本 | 定位 |
|---|---|---|
| `.html` | `make_lesson_html.py` | A4 排版、可编辑、可一键转 PDF |
| `.pdf` | `html_to_pdf.py` | A4 打印稿，可直接送打印机 |
| `.md` | `make_lesson_md.py` | 纯文本，便于传阅、粘贴、再加工 |

HTML 版的要点：

- 版面固定 **A4（210mm × 297mm）**，屏幕上呈现纸张效果，打印/导出 PDF 时自动裁掉所有装饰
- 校徽位于**信笺抬头层**（左徽 + 校名中英文 + 右上模型标），**不做居中大图**，标题区以文字为视觉重心
- **正文可直接在浏览器里点击编辑**，且不影响排版（详见"正文可编辑"一节）
- HTML 内置顶部操作条：**「编辑正文」「保存副本」「一键生成 PDF」**按钮（另有 A- / A+ 字号微调）
- 所有排版由脚本统一控制，无需手写 HTML/CSS

Markdown 版的要点：

- 与 HTML 版**共用 `scripts/plan_common.py`** 的角色句与行内标记解析，两条渲染路径不会漂移
- 环节卡片渲染为四级标题 + 列表，键值行渲染为 `- **键：** 值`，单行提示渲染为 `> 引用`
- 表格单元格自动转义竖线与换行；无表头时退化为两列键值表；小节标题深度封顶 `#####`，不会产出无效 Markdown
- **多行内容（板书设计、思维导图、流程步骤）必须用 `block` 字段，渲染为 ` ```text ` 围栏代码块**；即便误写进 `note`，脚本也会自动降级为代码块（详见"行首标记污染"一节）
- **MD 文件必须每次都生成**，它是三份交付之一，不是可选项

### 行首标记污染（重要，勿回退）

**HTML 和 MD 都是逐行提取文案的下游来源**——用户会拿它们做课件、贴文档、喂其他 AI。若某一行行首带上 `>`、`*`、`|` 这类标记，下游逐行提取时会把它们当成正文内容，表现为「每句话前面挂一个 `>`」这类污染。

已修复的历史问题（两个，两处都要防）：

1. **MD 版**：早先渲染 `note` 时给**每一行**都加了 `>`（`"> " + text.replace("\n", "\n> ")`）。板书设计天生是多行块文本，于是整段板书的每一行都成了引用行。抬头信息也曾用 `> ` 起头。
2. **HTML 版**：早先 `ce()`（生成可编辑节点属性的辅助函数）末尾 `return out + ">"`，而所有调用处模板写成 `<p%s>文字</p>`——`ce()` 提供了闭合 `>`，模板里**又跟了一个**，产出 `data-ph="学校名称">>呼和浩特市实验中学`。全文 97 处 `">>"`，纯文本提取后 221 行里 97 行以 `>` 开头。

因此约定如下，改动任一渲染器时都必须遵守：

- **`ce()` 只返回属性串，绝不返回结尾的 `>`**。调用处统一写 `<p%s>文字</p>`，闭合符由模板提供。这是唯一的属性出口，别绕过它手写 `contenteditable`
- **`build()` 末尾的 `">>"` 自检断言不得删除**。它把这类静默 bug 变成生成时立即报错：
  ```python
  if '">>' in doc or ">>" in doc.replace("&gt;", ""):
      raise AssertionError("HTML 自检失败：检测到多余的 '>' ...")
  ```
  注意判据要用精确的 `">>"`；单用 `'>>' in doc` 会把正常的 `data-ph="y">` 误判
- **禁止对多行内容逐行添加块级标记**。多行内容一律走 `block` → ` ```text ` 代码块（MD）/ `.note.block` 保留换行与全角空格缩进（HTML），缩进层级原样保留，且不含任何标记
- **抬头信息用纯文本**（`学校 ｜ 模型`），不加 `>`
- `>` 只允许出现在**单行** `note` 上（一句简短提示）
- 若必须新增块类型，先想清楚它会不会被下游逐行提取；会的话就用代码块或纯文本，不要用引用/列表等需要行首标记的语法

**新增字段必须所有渲染器同时支持**。曾把plan 里的 `note` 迁到 `block`，只给 MD 加了支持，HTML 版不认新字段，板书内容在网页里直接消失。改 `plan_common.py` 之外的字段契约时，HTML 与 MD 两端都要同步改，并各自跑一遍生成核对。

## 正文可编辑（重要）

用户拿到 HTML 后常要改字、改学情、补环节。模板把所有文字区域（标题、段落、列表项、卡片标签与内容、表头与单元格、键值行、提示框、各级小节标题、校名与模型标）都做成**纯文本可编辑**，用户在浏览器里点一下就能改，改完点「保存副本」得到新文件。

**为什么改字不会弄乱版式**——三点设计约束，缺一不可：

1. **用 `contenteditable="plaintext-only"` 而非 `true`**：只接受纯文本。用户从 Word / 网页粘贴进来的 HTML 与内联 CSS 会被浏览器剥除，无法注入字号、颜色、背景。
2. **全局拦截 paste，只取 `text/plain`**：剪贴板没有纯文本时（部分 Word 复制场景），退回剥掉 HTML 标签取文字，同样不执行任何样式。绝不放行富文本。
3. **样式只由样式表控制**：可编辑能力只加 `class`，不加内联 style，因此既定版式（字号、间距、配色、缩进、卡片分组、打印分页规则）不可能被用户改坏。

辅助细节：

- **空段落占位**：删空后浏览器会留 `<br>`，`:empty` 伪类失效，故由 JS 打 `.is-empty` 类，再用 `::before{content:attr(data-ph)}` 显示灰色提示（如"点击输入段落文字"）。生成可编辑节点时**必须带 `data-ph`**，统一走脚本里的 `ce()` 辅助函数，不要另写裸 `contenteditable`。
- **编辑态痕迹仅限屏幕**：hover / focus 的淡绿、淡蓝底与描边写在 `.editing` 作用域内，`@media print` 里全部 `!important` 清除；空的占位提示在打印时也不显示。
- **退出编辑态**会移除 `spellcheck`（关闭浏览器红色波浪线）与选区高亮，并把「保存副本」按钮收回隐藏。
- **保存副本**用 `cloneNode` 导出：剥掉 `contenteditable`、`spellcheck`、`is-empty`，保留全部样式与 base64 校徽，产出干净的定稿文件。

实测结论（Edge 无头验证）：粘贴携带恶意 `<span style="font-size:40px;color:red;background:yellow">` 时，目标节点的 `style` 属性为空、字号与颜色不变；向活动卡片灌入 1400+ 字超长内容后页面宽度不变、无横向溢出。

## 版面结构（自上而下）

1. **顶部品牌色条**：蓝 26mm + 绿 9mm + 灰细线，建立色彩秩序
2. **信笺抬头**：白底圆托盘托住校徽（直径 18mm），右侧校名（中文 13pt 加粗 + 英文 6.6pt 大写字距），最右蓝色胶囊承载教学设计模型
3. **细分隔线**：左 18% 为校徽蓝，余为浅灰
4. **标题区**：《课题名》教学设计（居中、19.5pt），下方副标题与蓝绿双色饰线
5. **基本信息表** → **正文各章节**

设计原则：**校徽是识别件而非装饰件**。放在页眉层与校名并列，尺寸克制（18mm），不得放大为居中主视觉，也不得与标题争夺重心。

## 校徽与配色（重要）

模板的整套配色**取自校徽**，两者严格同源，视觉上天然统一：

| 角色 | 色值 | 用途 |
|---|---|---|
| 校徽蓝（主色） | `#2458A5` | 各级标题竖线、信息表标签底色、表头、提示框、模型胶囊 |
| 校徽蓝（深） | `#1B427C` | 校名文字、信息表标签文字（保证小字对比度） |
| 校徽绿（辅色） | `#52B05A` | 环节卡片标签底色、二级标题竖线、色条与饰线右段 |
| 校徽绿（深） | `#3D8A44` | 环节卡片标签文字 |

- 校徽图片位于 `assets/badge.webp`（同目录另有 `badge.png` 备用），脚本自动读取并**内嵌为 base64**，因此产出的 HTML 是可独立分发的单文件，不依赖外部图片
- 校徽缺失时模板会自动降级为「无校徽」排版，不会报错
- 用户若要求换配色或去掉校徽，在 plan JSON 中设 `"badge": false` 即可关闭校徽

## 工作流程

### 第一步：确认课题
课题标题通常随用户请求给出；若未给出，先请用户提供课题标题，不要自己编题。

### 第二步：第一轮澄清——基本信息
用 AskUserQuestion 一次问齐以下 4 项；用户在请求中已明确给出的项直接采用，不再重复问。每题给 2-4 个结合标题推断出的候选选项，推荐项放首位并标注"(Recommended)"。

1. **学科与学段年级**：根据标题内容推断候选。例如《草船借箭》→小学语文五年级／初中语文。
2. **课时安排**：1 课时(Recommended)／2 课时／多课时单元整体设计。课时决定可选模型的颗粒度，必须问清。
3. **教材版本**：结合学科与年级给候选，如统编版／人教版／北师大版／苏教版／其他。**此项必须由用户明确指定，禁止代替用户默认**；用户说"随便／你定"时，仍需列出候选请用户从中选定，不得跳过。
4. **学情与特殊要求**：常规班级(Recommended)／基础薄弱需放慢夯实／基础较好可拓展提升／大班额需增加互动讨论／公开课或需融合信息化手段。

### 第三步：第二轮澄清——确定教学设计模型
先按下方"模型推荐规则"从第一轮答案推断最适合的模型，再用 AskUserQuestion 问一题"**教学设计模型**"：结合本课题场景给 3-4 个候选（含单模型与常见组合），推荐项放首位并标注"(Recommended)"，每个选项的 description 写明该模型是什么、为什么适合本课。用户表示"随便／你定"时取推荐项，并在最终交付说明中声明。

**模型推荐规则**（按优先级从上到下判断，命中即作为推荐项）：

1. 课时为"多课时单元整体设计"，或用户提到精品课、大单元教学、单元整体设计 → 推荐 **UbD**（并给"UbD＋BOPPPS"或"UbD＋5E"组合选项：UbD 定单元框架，单课时用 BOPPPS/5E 落地）。
2. 用户提到线上课程开发、教师培训、校本课程、完整课程项目 → 推荐 **ADDIE**。
3. 用户提到真实任务、项目式、案例教学、实践活动驱动 → 推荐 **PBL/CBL**（可给"UbD 或 PBL＋BOPPPS"组合选项）。
4. 理科科目（科学、物理、化学、生物）且为公开课或用户提到探究、实验、发现式学习 → 推荐 **5E**。
5. 学情为大班额，或用户提到希望增加学生讨论、生生互动 → 推荐 **对分课堂 PAD**。
6. 技能型课程（写作技法、实验操作、体育动作、编程语法、解题方法等）需要循序渐进掌握 → 推荐 **GRR**。
7. 以上信号均不明显 → 推荐 **BOPPPS**（通用默认）。

**组合规则**：

- 最多两个模型组合：一个单元/课程级模型（UbD、ADDIE、PBL）作主框架，叠加一个单课时模型（BOPPPS、5E、PAD、GRR）作课时执行框架。
- 同颗粒度模型（如 BOPPPS＋5E）默认不组合；用户坚持时以一个为主干、只吸收另一模型的特色环节，并在交付说明中说明融合方式。
- 用户明确指定某一模型时尊重用户选择，即使与推荐规则不一致。

### 第四步：核实教学内容
若课题不是有把握的经典篇目或知识点，先用 WebSearch 查该课在教材中的定位、内容要点与常见教学重点，避免编造知识性内容（具体公式、史实年代、原文引用等必须准确）。

### 第五步：撰写教学设计
撰写前读取两个参考文件：

- references/core_competencies.md：各学科核心素养维度，用于撰写教学目标。
- references/design_models.md：所选模型的环节框架与"文档结构映射"，用于组织教学过程与全文结构。

按下方"设计文档结构"与所选模型的要求撰写全文，同时把内容组织成脚本所需的 JSON（见"JSON 结构"）。

**撰写要点**：教学过程的每个环节写成 `activities` 里的一项（`label` 为环节标题，`items` 为教师活动／学生活动／设计意图等条目），这样会渲染成带色标的卡片块，比普通段落更清晰、更适合打印阅读。

### 第六步：生成三份文件并交付（HTML + PDF + MD）

**脚本位置**（用绝对路径调用，`<技能目录>` = `C:\Users\Admin\.workbuddy\skills\实验课程设计大师`）：

1. 将 JSON 写入临时文件，**必须 UTF-8 编码**。
2. 生成 HTML：
   ```
   python <技能目录>\scripts\make_lesson_html.py <plan.json> <输出.html>
   ```
   零依赖，纯标准库，不需要安装任何包。
3. 生成 Markdown（必做，每次交付都要有）：
   ```
   python <技能目录>\scripts\make_lesson_md.py <plan.json> <输出.md>
   ```
4. 生成 PDF（推荐，一次到位）：
   ```
   python <技能目录>\scripts\html_to_pdf.py <输出.html> <输出.pdf>
   ```
   该脚本调用本机 Edge / Chrome 的无头打印，输出即为 A4 尺寸 PDF，可直接送打印机。若本机没有 Edge / Chrome，脚本会提示改用 HTML 内置按钮，此时仍交付 HTML 与 MD。
5. **交付顺序**：一次 `present_files` 交付三个文件，顺序为 **HTML → PDF → MD**。HTML 排版最好、放首位；PDF 便于直接打印；MD 便于传阅与再加工。
6. 输出文件名：三者同名，仅扩展名不同。例如《草船借箭》教学设计（BOPPPS 模型）.html / .pdf / .md、《浮力》单元教学设计（UbD+BOPPPS 组合）.html 等；默认放在项目输出目录。

### 三份文件各自的用途

| 文件 | 用途 | 不适合 |
|---|---|---|
| HTML | 正式存档、打印预览、直接在浏览器里改字 | 传阅（体积大、需浏览器） |
| PDF | 送打印机、提交材料、离线归档 | 再编辑 |
| MD | 粘贴到群聊/公众号/文档、版本比对、再加工、喂给其他 AI | 打印排版 |

**关于「一键生成 PDF」**：HTML 顶部操作条的按钮调起浏览器打印对话框。用户若问怎么用，说明：目标打印机选「另存为 PDF」→ 纸张 A4 → 边距「默认」→ 勾选「背景图形」→ 保存。版式已按 A4 排好，无需再调整。

**关于「编辑正文」**：说明用户点「编辑正文」后可直接在页面里改字，hover 处会有淡绿底提示可点；改完点「保存副本」下载改好的 HTML，再点「一键生成 PDF」出稿。原始文件不会被覆盖，改坏了重新生成即可。用户若只想微调内容，也可以直接告诉 agent 改 JSON 重新生成，不必自己动手编辑。

用户要求修改时：更新 JSON 重新生成 HTML、MD 与 PDF，覆盖同一组文件、以 update 方式重新交付，不新建版本。**三份文件必须同步更新，不可只改其中一份**，否则内容会不一致。

## 设计文档结构

- **标题**：《课题名》教学设计（**标题内不写模型名**，模型名走页眉 `meta.tag`）。校徽印在页眉层，不进标题区。
- **基本信息表**（`info_rows`）：学科、学段/年级、课时、教材版本、课题、教学设计模型。渲染为两列并排的蓝底标签表格。
- **一、教材分析**：本课在教材/单元中的定位与作用，与前后内容的衔接。
- **二、学情分析**：结合用户给出的学情；学生已有基础、生活经验与可能遇到的障碍。
- **三、教学目标（核心素养导向）**：3-5 条，按该学科 2022 版课标核心素养维度撰写（撰写目标前读取 references/core_competencies.md）。每条用可观察、可检测的行为动词（如"说出、归纳、运用、解释"），禁用"培养综合能力"类空话。
- **四、教学重难点**：用 `kv` 写成"教学重点／教学难点／突破策略"三行键值结构。
- **五、教学过程**：用 `activities` 逐环节展开，每环节一项 `label` + 若干 `items`（教师活动／学生活动／设计意图）。
- **六、作业设计**：用 `activities` 分"基础巩固（必做）""拓展提升（选做）"两项。
- **七、板书设计**：用 `block` 字段写多行板书结构（HTML 版为提示框，MD 版为代码块，缩进原样保留）。**不要用 `note`**——多行进`note` 会在 MD 里逐行带上 `>`，下游做课件时表现为「每句话前面一个 `>`」。
- **八、教学反思（预设）**：留 2-3 条供课后填写反思路径的提示。

## JSON 结构

脚本 `scripts/make_lesson_html.py` 读取如下结构的 JSON 文件。所有字段均为可选（除 `title` 与 `sections` 外），按需使用。

**顶层字段**

- `title`（必填，字符串）：文档大标题。**标题只写课题名，不要重复模型名**（模型名会显示在页眉胶囊上）。
- `subtitle`（可选，字符串）：副标题，如"统编版小学语文五年级下册 · 40 分钟"。
- `meta`（可选，对象）：抬头层信息，字段均可选：
  - `school`：校名，默认「呼和浩特市实验学校」
  - `school_en`：英文校名，默认 `Hohhot Experimental Middle School`
  - `tag`：右上角胶囊文字，通常写教学设计模型名，如「BOPPPS 模型」；留空则不显示
  - `left` / `right`：旧字段，`school` 未设时回退用 `left`
- `footer`（可选，字符串)：页脚文字，默认同 `title`。
- `badge`（可选，布尔)：是否显示校徽，默认 `true`；设为 `false` 可关闭。
- `info_rows`（可选，数组)：基本信息表，每项为 `[标签, 内容]` 二元数组，脚本自动两两并排成行。
- `sections`（必填，数组)：正文小节。

**section 内字段**

- `heading`（字符串）：小节标题，如"一、教材分析"。
- `paragraphs`：字符串数组，正文段落（首行缩进两字）。以"教师活动：""学生活动：""设计意图："等开头的句子会自动加粗前缀。
- `bullets`：字符串数组，圆点列表项。
- `numbered`：字符串数组，有序列表项。
- `activities`：数组，**教学过程推荐用此结构**。每项为 `{"label": "环节一 B 导入（约 5 分钟）", "items": ["教师活动：…", "学生活动：…", "设计意图：…"]}`，渲染为带色标的卡片。
- `table`：`{"header": ["表头1","表头2"], "rows": [["a","b"],["c","d"]]}`，带表头底色的表格。
- `kv`：键值数组 `[["教学重点", "梳理故事情节"], ["教学难点", "…"]]`，渲染为左标签右内容的行。
- `note`：字符串，渲染为米色提示框。**只适合单行简短提示**；多行内容误写进来时，MD 版会自动降级为代码块，但 HTML 版仍按提示框渲染，所以多行内容请改用 `block`。
- `block`：字符串，**结构化多行内容专用**（板书设计、思维导图、流程步骤、层级大纲）。HTML 版渲染为提示框，MD 版渲染为 ` ```text ` 围栏代码块，缩进与层级原样保留。板书设计必须用这个字段。
- `page_break`（布尔）：为 `true` 时该小节另起一页。
- `subsections`：子小节数组，字段同上，可递归嵌套（用于需要再分层的复杂结构）。

**行内标记**：正文中用 `**文字**` 渲染为加粗，`__文字__` 渲染为校徽绿浅底着重标记。

最小示例：

```json
{
  "title": "《草船借箭》教学设计",
  "subtitle": "统编版小学语文五年级下册 · 40 分钟",
  "meta": {
    "school": "呼和浩特市实验学校",
    "school_en": "Hohhot Experimental Middle School",
    "tag": "BOPPPS 模型"
  },
  "badge": true,
  "info_rows": [["学科", "语文"], ["学段/年级", "小学五年级"], ["课时", "1 课时（40 分钟）"], ["教材版本", "统编版五年级下册"], ["课题", "草船借箭"], ["教学设计模型", "BOPPPS"]],
  "sections": [
    {"heading": "一、教材分析", "paragraphs": ["本课是……"]},
    {"heading": "三、教学目标（核心素养导向）", "bullets": ["**语言运用：** 能说出……"]},
    {"heading": "四、教学重难点", "kv": [["教学重点", "……"], ["教学难点", "……"]]},
    {"heading": "五、教学过程", "activities": [
      {"label": "环节一　B 导入 Bridge-in（约 4 分钟）", "items": ["教师活动：……", "学生活动：……", "设计意图：……"]}
    ]},
    {"heading": "六、作业设计", "page_break": true, "activities": [
      {"label": "基础巩固（必做）", "items": ["……"]},
      {"label": "拓展提升（选做）", "items": ["……"]}
    ]}
  ]
}
```

## 硬约束

- 不跳过两轮澄清，除非用户已给齐信息或明确要求直接生成。
- 教材版本必须由用户明确指定，禁止默认代替。
- 教学过程必须按所选模型的环节框架撰写；组合模型不超过两个，且颗粒度须兼容（单元/课程级主框架＋单课时执行框架）。
- 后测/评价证据必须与教学目标逐条对应；教学目标必须落到具体学科核心素养维度。
- 不编造课文内容、史实、公式等知识性信息；拿不准先搜索。
- **一律以 A4 尺寸交付** HTML 与 PDF，方便打印；两者均不得改成其他纸张规格。
- **每次交付三份文件：HTML、PDF、MD**，缺一不可。修改内容时三份必须同步重新生成。
- 校徽与校徽配色是模板的固定组成部分，产出教案须带校徽（除非用户在 JSON 中设 `badge: false`）。
- 教学过程优先用 `activities` 结构（而非纯段落），保证打印时的卡片分组与可读性。
- **可编辑节点一律通过 `ce()` 生成**，不要手写裸 `contenteditable`，否则会漏 `data-ph` 导致删空无占位提示。
- **角色句与行内标记的解析只写在 `scripts/plan_common.py`**，HTML 与 MD 两个脚本都从这里导入，不要在各脚本里另写一份。
- 只交付最终 HTML、PDF、MD，不交付 JSON、脚本等中间文件。
- 脚本零依赖，用任意 Python 3 直接运行，不需要 `pip install`。
